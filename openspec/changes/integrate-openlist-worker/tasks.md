# Tasks

## 1. 验证隔离 Worker 与文件接口

- [ ] 1.1 从官方 `OpenListTeam/OpenList-Worker` 当前默认分支解析一个候选提交，在隔离 Cloudflare Worker 上用生产拟用的存储驱动部署。用 `cf` CLI 验证候选制品上传、部署标识查询和回退能力，记录命令、制品来源、存储驱动及对应源码提供方式。
- [ ] 1.2 挂载包含多页目录、嵌套目录、Unicode 文件名和已知字节文件的只读夹具。从站点的隔离测试来源用 Chromium 验证 `POST /api/fs/list`、`POST /api/fs/get`、`raw_url` 实际下载链和 `206`/`Content-Range` 可读性，记录请求与响应的脱敏结果。用服务端权限确认该读取身份无法修改夹具。

## 2. 接入文件系统

- [ ] 2.1 在 `packages/vfs` 实现 OpenList-Worker `GameSource`。测试覆盖分页、路径规范化和根边界、文件与目录元数据、HTTP 和 JSON `code` 错误、签名下载链接刷新、可信下载来源，以及 `200`/`206`/无效范围与超限取消。
- [ ] 2.2 通过 `packages/core` 的来源描述和 `openSource()` 恢复已配置的远程根。协调共用文件的负责人，以站点现有启动入口和合成游戏夹具验证读取、归档范围读取和可写覆层。回归本地来源的打开流程，并检查来源描述和日志仅含非敏感配置。
- [ ] 2.3 将 1.2 的实测整理为候选和生产共用的浏览器契约套件。使用已知合成字节校验整文件和中间范围，并用错配字段、错误状态、缺失跨域响应头和不匹配字节证明断言会失败。

## 3. 每日检查和滚动发布

- [ ] 3.1 新增独立的 GitHub Actions 日检和手动补跑入口。每次解析官方仓库当前默认分支和 HEAD，验证同一 SHA 的候选制品并并行检查当前生产部署。验证上游 HEAD 变化、默认分支切换、HEAD 未变化和上游查询失败四种情况，并确认每个目标的实际请求结果可单独追溯。
- [ ] 3.2 添加检查失败通知和独立的缺跑监控。通过一次失败和一次缺跑演练验证告警实达，并确认手动补跑能更新记录。运行记录注明 UTC 时间、候选 SHA、部署标识、制品摘要和失败的契约项。
- [ ] 3.3 接入发布门禁。在隔离环境验证失败候选被阻止、通过的候选制品摘要与发布制品一致，以及发布后契约失败时回退并复测。构建上游候选的任务使用隔离权限，核对生产凭据只进发布任务。对涉及存储迁移的候选一并记录隔离升级和恢复结果。

## 4. 联调验收

- [ ] 4.1 执行首次生产发布并记录 Worker 部署标识、制品摘要及 Chromium 契约复测结果。取得下一次日检对候选和生产都发出实际请求的记录。在 `tasks.md` 追加运行链接和验收结果。
- [ ] 4.2 按团队约定协调共享产物，运行本变更相关测试、`npm run check` 和 `openspec validate integrate-openlist-worker --strict`，记录结果并将本变更的实现提交按仓库流程交付。
