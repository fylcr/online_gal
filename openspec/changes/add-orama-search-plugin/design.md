# Design

## Context

- `redesign-frontend` 3.5–3.7 已定义导航栏入口、浏览器内搜索与基础筛选。本变更只替换搜索计算路径，复用同一输入框和列表。
- `plugin-system` K3、K11、K21 分别规定内核不执行插件代码、官方安装 API 和发布装配边界。非管理器插件目前没有通用执行器，本次只给官方管理器接一个已知的搜索入口。

## Goals / Non-Goals

- 名称、标题、标签可全文检索，中文、日文和拉丁字母混合库可用，现有引擎筛选和排序继续工作。
- 首屏不下载搜索执行资源，查询和索引都留在浏览器。无法执行插件时，基础筛选仍能用。
- 不新增插件通用执行器、路由、权限、VFS 能力、向量搜索或远程目录检索。

## Decisions

### 1. 独立发布包与按需加载

`plugin-system` 负责 `packages/plugins/search/` 的源码、依赖、manifest 与构建。使用现有的 format 2，固定 ID `online-gal.search`、官方来源、当前插件 API 版本，不声明 `role: manager` 或特权能力。把 Orama 与分词资源打入一个独立的浏览器 Worker 入口 `search-worker.js`。管理器不直接依赖 Orama；SW 内核不打包或执行 Orama。

管理器收到第一条非空查询后先给出基础筛选结果。已有 SW 控制页面时，查已有的内核状态；未安装且允许自动安装时，经官方注册表安装该 ID。只启动内核按已校验的官方包提供的同源 `/__plugins/online-gal.search/search-worker.js`，不从注册表 URL、CDN 或第三方来源直接执行 JS。官方信任策略沿用内核，验签失败不得绕过。并发输入合并同一次加载；无 SW、离线且未缓存、包缺失或加载失败始终可用基础筛选。用户从内核卸载后保留卸载决定，不因继续搜索或刷新而自动装回，除非显式重装或重置插件状态。以已有内核状态为准；如没有持久化的卸载标记，由 plugin-system 在既有状态、安装/卸载操作中补充该插件的标记与自动安装判定（在状态操作队列内判断），不新增路由或权限。已存在的用户安装动作仍应可以显式重装。

### 2. Worker 协议与索引生命周期

- Worker 只接收序列化的 `{ id, name, title?, tags }`、查询词和控制消息。无游戏源对象、路径、目录句柄、存档、封面、授权令牌；不扫描游戏文件。Worker 是计算隔离，不作为同源安全沙箱；只执行上述官方包。
- 协议 v1 用 `ready` 握手，`{ type: 'replace', revision, records }` 替换当前索引并返回 revision，`{ type: 'query', revision, requestId, term, offset, limit }` 返回对应的 `{ revision, requestId, ids, total }`。错误返回有限错误码，不包含原始词或元数据。管理器仅接受当前快照和最新查询的结果，把 ID 与当前记录相交；按页取齐所需 ID，不被 Orama 默认结果条数静默截断。现有排序和按引擎筛选仍由管理器决定。
- 使用 Orama 本地全文搜索。名称、标题、标签均建立索引，按查询与字段采用同一规范化流程。评估官方文档中的 `@orama/tokenizers/mandarin`；仍须用真实混合语言样本验证中文、日文和拉丁匹配。如果该配置不能通过，使用经测试的本地分词方案接入 Orama，而非改用云服务或为特定测试写匹配特例。
- 游戏库导入、编辑或删除成功后，以权威库快照更新索引。可先做合并触发的内存全量重建，切换 revision 时继续用基础筛选。加载时读取最新快照，不以索引为数据源。输入乱序、切页、插件更新、卸载时丢弃过期结果；离开游戏库或搜索会话销毁时终止 Worker，更新后从新代重建。索引仅驻内存，不额外持久化。
- 只有加载、安装与更新插件所需的静态资源允许联网请求；查询词与索引数据不参与 URL、Fetch 请求、遥测或日志。禁止 Worker 调用 Orama Cloud 或任何网络 API；用浏览器请求记录核对。

### 3. 发布与切换

- 按 K21 的制品约束，通过 GitHub Actions 生成独立的 format 2 搜索制品与锁定引用，记录源码 SHA、制品摘要与版本；Pages 站点分支验证、装配并发布同源官方注册表，沿用既有签名和原子更新。搜索包不复制到管理器根目录。安装/更新阶段不能改写已验的文件；setup 分支不取搜索包，不新增配置密钥。
- 生产装配依赖 K21 / 12.5。此前可用本地站点夹具和隔离 Pages 验证；不因插件延迟交付而阻塞既有导航栏搜索和固定外壳。部署失败按上一可用制品/部署回滚；客户端遇缺包或接口不兼容时不撤销基础筛选。

## Risks / Trade-offs

- 分词选择影响混合语种结果，用中、日、英、标点/全半角和同名记录验收。记录 Worker 大小、冷启时间与大库重建；若重建成本偏高再演进增量索引。
- 缓存、控制权切换或延迟响应可能导致新旧结果交错。以请求 ID、数据 revision 和 Worker 实例身份丢弃迟到响应，保留基础筛选作为始终可用的路径。

## Migration Plan

先实现包与协议，再接游戏库入口和降级。按隔离环境验证发布、签名、FCP 与离线，达到验收条件后再更新生产锁；保留上一可用制品引用。
