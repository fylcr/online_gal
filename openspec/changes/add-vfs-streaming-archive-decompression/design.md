# Design

## Context

`packages/vfs/src/archives/zip.ts` 已有 `ByteSource` 偏移输入。ZIP 解析器按范围查中央目录，解压时仍一次读取成员的全部压缩字节。现有 `ArchiveReader` 暴露索引和整成员读取。 `packages/core/src/library.ts` 的 `withArchives()` 会把 `GameSource` 里的包读成 Blob，须改为从原始来源按范围打开。引擎继续从宿主接口读取字节，解包由 VFS 负责。

## Goals / Non-Goals

- 同一归档接口覆盖 ZIP、7z、RAR4 和 RAR5，支持本地文件以及可按范围读取的网络输入。
- 按需建索引、读取指定成员的解压字节流和连续区间，并为现有整成员调用保留有界兼容入口。
- 浏览器使用静态发布的 JS 和 WASM 运行解码器。压缩包格式的写入和创建属于独立变更。

## Decisions

### 1. 复用 VFS 的字节输入和游戏来源

- 将 `ByteSource` 提取为各个归档格式共用的接口，使用已知大小及可取消的偏移读取。Blob 使用 `slice()`，网络用来源的 `readRange()`。归档打开、探测和恢复走同一条路径，并检查适配器真正支持范围读取。直链沿用已有传输接口，WebDAV 通过 `integrate-webdav-source` 的 `GameSource` 接入。
- 网络读取校验响应区间和长度，远端忽略 Range 或缺少适用的 CORS 能力时返回明确错误。对支持资源版本校验的来源固定归档版本，发现长度或版本变化后要求重新打开，避免将不同版本的区块拼接。限制并发与读取窗口，取消时中止请求和释放缓存。
- 按签名选择 ZIP、7z、RAR4/RAR5，更新归档扩展名登记。归档作为只读成员层保留，归档原文件继续按路径可读，供已有 WASM 适配器自行挂载。可寻址来源通过 `openGameSourceArchive()` 打开成员层，原包可访问性和松散文件优先级跟随现有来源规则。当前 XP3、NSA、NS2、SAR、ASAR 的归档路由和存档覆层继续沿用。

### 2. 库选型与验证范围

| 格式 | 首选 | 需要在浏览器验证 |
| --- | --- | --- |
| ZIP / Zip64 | [@zip.js/zip.js](https://github.com/gildas-lormeau/zip.js) | 用 VFS 偏移读适配 Reader，向有背压的 `WritableStream` 输出。验证文件头、中央目录和目标成员的范围，STORED 直读、DEFLATE 分块、Zip64 和至少一种库支持的加密 ZIP。按浏览器能力选择原生或库内解压，记录实际发布的资源。 |
| 7z | [7z-wasm](https://github.com/use-strict/7z-wasm) | 在专用 Web Worker 验证 `WORKERFS` 挂载本地 Blob 和分块偏移读取，另行验证远端读取桥接和分块输出。上游示例提取到虚拟文件系统，再调用 `FS.readFile()`。需证明二进制或定制构建可以接到受控输出端。 |
| RAR4 / RAR5 | [libarchive](https://github.com/libarchive/libarchive) 自行构建浏览器 WASM | 分别验证 RAR4/RAR5 格式处理器，使用其 read/seek 回调和 `archive_read_data_block()` 对接 VFS，证明目录读取和逐块输出。核对 [node-unrar-js](https://github.com/YuJianrong/node-unrar.js) 2.0.2 的浏览器入口，其 `createExtractorFromData` 接收整包 `ArrayBuffer`，提取结果为成员 `Uint8Array`。仅在有可验证的偏移输入、逐块输出和适用分发许可证的版本时列为备选。 |

7z 与 RAR 的 C/C++ 回调通常是同步接口。先验证 Emscripten 异步桥接能否在同源专用 Worker 挂起解码并等待 VFS 分段请求。若改用共享缓冲和独立 I/O Worker，须在实际站点验证 `crossOriginIsolated` 与所需跨源资源均可工作。各格式先证明输入和输出两侧都满足字节预算，再接入正式路径。若首选失败，记录上游版本、缺少的接口和测量结果，继续验证用户列出的同格式候选或具备所需接口的构建。

ZIP 加密按验证过的算法公布支持矩阵，单次打开或读取可使用运行时密码。7z 和 RAR 首版测试普通单卷及 solid，其他变体依实际结果在能力矩阵注明。记录构建采用的具体源码版本、WASM 构建命令、许可证及通知。7z 构建审核 RAR 相关模块的额外许可，优先使用仅含所需 7z 能力的构建。

### 3. 区间、流与资源生命周期

- `ArchiveReader` 提供按路径打开成员流、按解压后偏移读取及关闭。归档 `GameSource.readRange()` 调用成员范围读取，既有 `readFile()` 在适用上限内收集流。按格式和成员记录直读、顺序解码、加密和完整性校验的能力。
- 无加密且可直接映射的 STORED 成员将解压后区间映射到归档偏移。DEFLATE、LZMA2 与 solid 成员从格式允许的解码起点开始，逐块丢弃目标范围前的解码结果，完成所需区间后停止。solid 包的相同压缩块可以包含多个成员，请求后部内容的成本受该块长度影响。完整读取完成时校验格式提供的完整性信息，提前结束的局部读取仅声明实际完成的检查。
- 输入窗口、索引字节与条目数、解码字典或工作内存、输出队列、整成员读取、解码总工作量与并发分别设定上限。以内存和网络计数实测收紧默认值，在实现任务记录。消费者背压限制消息队列，停止消费、取消挂载或解码失败时释放请求、解码器和 Worker。格式支持的资源上限在分配前检查，未知大小在逐块处理时累计计数。
- 归档成员名在建索引前检查，拒绝路径越界、绝对路径、链接及歧义重名。成员保持虚拟只读路径，写入通过现有本地覆层。错误须区分不支持的格式或变体、需密码、密码错误、损坏、读能力缺失、资源预算超限及取消。密码仅保存在本次打开的内存上下文里。

## Risks / Trade-offs

- 7z/RAR 的 WASM 封装、固实块解码与桥接能力决定实际延迟。按格式用同一夹具记录读取偏移、传输字节、解码起点、首块输出和资源峰值。支持矩阵按来源、格式和变体发布。
- 解码器通过站点的既有静态资产构建按需加载。验证浏览器部署上的同源 Worker/WASM 加载、构建体积和未打开归档时的请求记录。
