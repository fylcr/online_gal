# Tasks

`file-system` 负责本变更的浏览器选型、VFS 和游戏库实现及验收。先用本地 Blob 和跨源 HTTP Range 夹具验证 ZIP 路线。ZIP 能力验证通过后即可实现共用接口和 ZIP 读取，同时推进 7z、RAR 的选型验证。各格式通过对应的第 1 节验证后即可接入第 2 节。第 3.2a 项在 WebDAV 可寻址挂载就绪后执行。

## 1. 浏览器选型验证

- [ ] 1.1 建立可重复的读取夹具及指标。为同一内容生成 ZIP/Zip64、7z、RAR4、RAR5，覆盖普通单卷、7z/RAR solid、至少一种 zip.js 支持的加密 ZIP。准备本地 Blob 和能够记录 `Range` 的跨源 HTTP 夹具。记录源读取的偏移、请求数和总字节、首块耗时、索引与解码器内存、在途输出峰值。记录夹具生成命令和预期哈希。
- [ ] 1.2 用 `@zip.js/zip.js` 验证自定义偏移 Reader、`WritableStream` 输出、STORED 成员直读、DEFLATE 分块、Zip64 和加密 ZIP。至少对一个大成员验证消费尚未完成时能收到首块。若关键接口不满足需求，按同样的输入与输出指标验证 `unzipit`，逐项记录其格式与加密支持。
- [ ] 1.3 用 `7z-wasm` 验证 Worker 内 `WORKERFS` 的 Blob 切片读取。对普通和 solid 夹具分别验证网络偏移桥接、成员分块输出及背压，测量 WASM 线性内存和 JS 队列峰值。若需要定制构建，记录所需读写回调、源码版本和构建命令。首选不满足时用相同指标验证 JS7z 或具备所需接口的 7-Zip 构建。
- [ ] 1.4 用 libarchive 浏览器 WASM 分别验证 RAR4/RAR5 的 read/seek 回调、索引读取、`archive_read_data_block()` 和中后段 solid 成员。针对缺失的变体记录复现；`node-unrar-js` 只有在能证明分段输入和分块输出，并核对可分发许可后才进入备选。用同一夹具对比原始文件字节、对网络的读取范围和输出实测峰值。
- [ ] 1.5 把各库的实测结果、没有通过的来源或变体、WASM/JS 体积、对应源码与许可证写回本任务节。按实际浏览器可用能力选择实现路径，给出索引、并发、输入、解码工作量、内存和输出预算的默认值及测试上限。

## 2. VFS 接口与格式实现

- [ ] 2.1 在 `packages/vfs/src/archives/` 共用 `ByteSource`。适配 Blob 切片和可寻址 `GameSource`，将大小、真实范围能力及可用版本验证信息贯穿打开和读取流程。覆盖请求取消、返回长度异常、远端拒绝范围和打开期间源版本变化。
- [ ] 2.2 扩展 `ArchiveReader` 的成员流、解压后范围、资源关闭接口和 `ArchiveGameSource` 的适配。将旧整成员调用接到有字节上限的路径。验证 STORED 直接读、压缩成员顺序跳过前缀、完整读取校验和取消释放。由 `packages/vfs/src/archives/index.ts` 登记 `.zip`、`.7z`、`.rar` 及签名检测。
- [ ] 2.3 接入通过第 1 节验证的 ZIP、7z、RAR 解码路径，每个格式的 Worker、WASM 与库资源仅在使用时加载。拒绝越界绝对路径、父目录跳转、链接和规范化后冲突。分别验证加密 ZIP 正确/缺少/错误密码、损坏数据、字典大小和索引超限、慢速消费、取消和重开。记录支持矩阵和诊断信息。

## 3. 游戏库与浏览器验收

- [ ] 3.1 将 `packages/core/src/library.ts` 的可寻址归档导入、打开和恢复接到 `openGameSourceArchive()`，保留原包路径和现有来源优先顺序。用合成游戏验证引擎宿主按范围读取成员，存档写入本地覆层。回归 XP3、NSA、NS2、SAR、ASAR 及既有 ZIP 打开路径。
- [ ] 3.2 在部署候选的真实浏览器里跑 ZIP/Zip64、7z、RAR4、RAR5 的本地 Blob 和跨源 HTTP 范围矩阵。比较输出哈希，并记录建索引、取首块、局部读、整成员读和取消的网络与内存数据。用大于缓冲预算的夹具证明局部访问无需预下载或将全部成员放入缓冲。复测跨源拒绝和 Range 被忽略的错误提示，验证未使用归档时不会请求对应解码器。
- [ ] 3.2a `integrate-webdav-source` 提供可寻址挂载后，在同一候选上用 WebDAV 重跑第 3.2 项的归档矩阵，另行记录实际 206 响应、请求范围、字节校验和失败场景。
- [ ] 3.3 写回来源与格式支持矩阵、预算和证据。格式或来源组合尚未验证时保留对应未完成项。按项目发布约定保存构建对应源码及许可通知，运行 `npm run check` 和相关测试，确认经 Pages 静态分发的 Worker/WASM 可加载。全仓构建前在频道广播确认共享产物空闲。
